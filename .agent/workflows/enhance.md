# /enhance [feature-name]

## Purpose

Add functionality, improve UX, or optimize an existing mobile screen.
For mockdata scaffolding: user must explicitly request it -- not generated by default.

## Pre-conditions

- [ ] Existing component folder exists in `src/app/views/mtbike/views/`
- [ ] `ng build` currently passes (no pre-existing errors)

---

## Steps

### Step 1 -- Identify Scope
- Action: Ask (or infer from request) what change is needed:
  1. What feature / component is being enhanced?
  2. What specifically changes? (new field, new API, UX fix, mockdata scaffold?)
  3. If mockdata requested: user must have explicitly said so -- do NOT auto-generate mockdata
- Gate: Enhancement target identified. Mockdata decision confirmed (real API default, mockdata only if user requested).

### Step 2 -- Read Current Code (ALL 3 files)
- Action:
  1. Read `mtb{NNN}-{abbr}-{feature}.component.ts`
  2. Read `mtb{NNN}-{abbr}-{feature}.component.html`
  3. Read `mtb{NNN}-{abbr}-{feature}.component.scss`
  4. Note all methods, their full signatures, and brace scoping
- Gate: All 3 files read. Method boundaries understood. Do NOT edit before reading.

### Step 3 -- Read Reference (if API change needed)
- Action:
  1. Read `mtbike-api-static.service.ts` (existing namespaces)
  2. Read `mtbike-api.service.ts` (existing methods)
  3. Read `mtb009-sal-consultant` as pattern reference if adding new API
- Gate: Reference patterns understood if API change needed.

### Step 4 -- Implement Changes
- Action: Apply changes following fe-pipeline SKILL patterns:
  - Edit `.ts` -- keep arrUnsubscribe, loader, openSet patterns intact
  - Edit `.html` -- 3-part layout, material-icons only, no inline styles
  - Edit `.scss` -- SCSS variables only, no hex colors
  - If mockdata was explicitly requested: add `loadMockData()` method with comment `// Mock -- remove when API ready`
  - One logical change at a time -- verify build after each file
- Gate: All edits complete. No unrelated code changed.

### Step 5 -- Register New APIs (if needed)
- Action: If new API methods added:
  1. Add APIID key to `mtbike-api-static.service.ts`
  2. Add Observable method to `mtbike-api.service.ts`
- Gate: If API added, both registration files updated. DLL namespace chain intact.

### Step 6 -- Build Verify (MANDATORY GATE)
- Action: `ng build`
  - 0 errors -> proceed
  - Errors -> fix immediately -> rebuild
  - 3+ failures on same error -> STOP: report to user
- Gate: `ng build` returns exit code 0. NEVER report done without passing build.

### Step 7 -- Report
```
[OK] Enhancement Complete
  Feature:   {feature name}
  Changes:   {what changed}
  Files:     {list of modified files}
  API:       Real API | Mockdata (user-requested)
  Build:     ng build -- 0 errors [OK]
```

---

## Banned
- DO NOT rewrite entire components when small changes suffice
- DO NOT change unrelated code during enhancement
- DO NOT generate mockdata unless user explicitly requested it
- DO NOT partially replace methods -- always include complete opening AND closing braces
- DO NOT report done without a passing ng build
